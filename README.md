Justification: By digitizing donor pledges and recipient needs, this platform ensures transparency and speed in critical medical situations. 🛠 Technology StackBack-end: Spring Boot 3.5.14, Spring Data JPA ORM: Hibernate 6.x Database: MySQL (5 Normalized Tables) Security: Spring Security (Role-based access: ROLE_ADMIN) Front-end: Thymeleaf Templates Concurrency: Spring @Scheduled & @Async for the Matching Engine Low-level Data Access: JDBC PreparedStatement fallback 🚀 Key Features (CO Mapping)[CO1] Concurrency: A multithreaded matching engine scans donor and recipient records every 30 seconds to find blood/tissue compatibility matches. [CO2] Web Deployment: Role-based access control ensures only authorized admins can register donors and view sensitive recipient data. [CO3] Full-Stack Integration: Implements a complete MVC architecture (Controller-Service-Repository) with Hibernate entity mapping and @Transactional support. [CO4] JDBC Fallback: Utilizes raw SQL via PreparedStatement for high-performance bulk updates of recipient urgency levels. 📂 Database SchemaThe project utilizes 5 normalized MySQL tables to manage data efficiently:donors: Stores donor pledges and medical data.recipients: Tracks patients waiting for transplants.organ_matches: Logs successful matches found by the engine.hospitals: Stores medical facility locations and contact info.users: Manages credentials and roles for Spring Security.🔧 Setup & InstallationDatabase: Create a MySQL database named organ_registry_db.Configuration: Update src/main/resources/application.properties with your MySQL username and password.Run: Open the project in Eclipse and run RegistryApplication.java.Access: Visit http://localhost:8081 (Port 8081 used to avoid conflicts).Login: Use credentials admin / admin123.
